# DailyNotes PC 网页富文本编辑：双端架构研究 R007

- 日期：2026-11-15。
- 需求背景：用户认为富文本编辑可放在 Web 服务上，便于 PC 浏览器利用键盘和大屏进行编辑、整理；此为新增的桌面网页入口需求方向，不等于用户已授权取消此前确认的手机 AppFlowy 风格编辑器。
- DailyNotes 现行基线：`docs/requirements/DailyNotes开发规范_V2.57.md` 的 DN-180～DN-183；本轮研究不是代码实施。
- 现有项目状态：`README.md` 明确为 UI-only 预览，`pubspec.yaml` 仅含基础 Flutter/UI 依赖，`.github/workflows/flutter-preview.yml` 仅用于 Flutter 预览构建。尚无真实本机持久化、WebDAV、编辑器、后台 API 或 PC Web 工程。
- 证据等级：源文档、当前用户仓库、公开技术说明的方案评估；未运行 Flutter Web、未登录坚果云验证 CORS、未搭建服务器、未进行双端数据测试。

## 一、需求拆解与重要歧义
用户提出的是「PC 可以打开 Web 服务来方便地使用富文本编辑」，可确认的目标是**PC 浏览器富文本编辑入口**，而不是必然将所有日记和数据移到服务器或取消手机上的富文本工具栏。Web 站点是前端界面，Web 服务可能包含后端/同步网关；数据主存位置、浏览器离线草稿的可靠性、服务器是否常开、访问范围（局域网/公网）、登录与加密均未定稿。

## 二、三种架构候选
A. 仅静态 Flutter Web 前端：优点是页面部署容易，AppFlowy Editor 框架/渲染逻辑有 Web 支持，部分正文编辑 UI 可复用；缺点是浏览器没有原生 Android SQLite/文件目录，持久化和跨设备互通需要独立实现。**不能默认静态网站能直接连接第三方坚果云 WebDAV**，后者受 CORS、身份验证与特殊 WebDAV HTTP 方法影响。若只使用浏览器存储作为唯一正本，还需应对清理缓存、配额、私密模式、浏览器账号变化、缓存丢失等风险，不能当作稳定保存方案。
B. 私有 Web 应用 + 受控后端：Flutter Web/其他编辑器前端 + 登录认证的 API + 服务器端持久化/同步网关，后端可向 WebDAV 发起经授权的同步请求并返回可靠的保存确认。优势：PC 使用便利、适配 CORS/凭据问题；不足：需要安全运维、 HTTPS、服务端数据库/备份、权限审计与更新。服务端不能成为没有备份的唯一正本，且不能绕过 DN-148 事务/事件协议。
C. 完全云端中心式：手机和 PC 每次编辑都需要云端可用，违背当前 Android 离线可靠和用户偏好手动同步，不作为推荐基线。

**推荐方向（待用户确认具体实现）**：A 的 Web 前端体验 + 必要时 B 的受控数据/同步网关；Android 仍为独立本机可用客户端，手机本地可靠落盘，不因 Web 服务不可访问而影响日常记录。网页同样应具备可靠的保存目标，无法提交到后端时不得显示“已保存到服务器”；如有离线草稿应标为“仅此浏览器草稿”并明确风险。Web 应用是否独立拥有持久化数据库、是否自托管及部署方式待另行选择。

## 三、建议的端到端数据流（候选）
- Android：编辑器文档 JSON → 独立业务实体/修订/附件映射 → 本机原子事务 + 持久化 outbox → **用户手动 WebDAV 增量同步**。
- PC 浏览器：加载用户授权的记录快照 → 使用兼容的富文本文档模型/桌面交互 UI 编辑 → 本机浏览器暂存（仅缓存/未确认草稿）→ 请求受认证 API 提交可靠 PC 端保存 → PC 端独立待同步队列 → 用户手动 WebDAV 增量同步。
- 两端共同：同一业务记录 ID/revision/appendId/附件 ID 及内容格式版本；操作日志/快照/检查点与冲突协议均遵循 DN-036～038、DN-147～151、DN-183。不同端的物理 SQLite/IndexedDB/文件目录不要求相同，但序列化协议一致。
- 若未来要求手机刚写 PC 立即可见，必须明确引入自动推送/自动同步/局域网直连之一，不能在「默认仅手动同步」下承诺实时一致。
- 同一笔记在手机、PC 都有未同步更改时禁止“最后写入覆盖”，必须检测公共祖先版本和修订冲突，提供可审查/恢复的副本或操作层级合并。

## 四、需要特别警惕的现实制约
1. **CORS**：MDN 的 CORS 文档说明浏览器跨域请求需要目标服务 CORS 策略支持；非简单方法触发 OPTIONS 预检，WebDAV 的 PROPFIND/PUT/MOVE 等及鉴权头很可能涉及此类限制。浏览器直接访问坚果云是否可用必须对实际端点测试，不能仅凭 Android 客户端成功就断言 Web 可用。
2. **坚果云 WebDAV 配额**：坚果云帮助中心当前说明需要专用第三方应用授权密码，并列有文件大小、请求频率和单请求列举数量限制。远端布局需考虑打包操作事件/检查点与分页，不能每敲一个字就提交一个 WebDAV 文件，也不能假设能无限请求。
3. **凭据**：禁止把第三方应用密码嵌入公开 Web 静态资源、仓库或浏览器可读取的长期明文设置。受控后端如果保存凭据，应采用授权隔离、最小权限、加密保护和审计；公开访问必须 HTTPS、身份认证、CSRF/CORS 防护及按业务校验。
4. **许可与 Web 兼容**：`appflowy_editor` 在 pub.dev 提供 Web 支持，但与完整 AppFlowy 的移动工具栏并非同一套即插即用部件；需要专门 PC Web 编辑器界面和快捷键/剪贴板/拖放测试。直接复制完整 App 的代码还涉及 AGPL-3.0 合规；独立包 AGPL-3.0/MPL-2.0 双许可。
5. **浏览器存储**：不能把 IndexedDB/Cache Storage 永久可靠性当作 Android 本机事务。要定义未确认草稿、后端已保存、待 WebDAV 同步、远端已同步四个明确状态；页面刷新/浏览器崩溃与同账号不同浏览器切换必须有可验证退路。
6. **迁移与回滚**：上游编辑器版本升级须通过相同富文本 JSON 的 Android↔Web 往返测试；未知区块保留原始数据或只读，不可静默丢格式；附件映射要跨不同存储路径，不能引用手机本机绝对路径。

## 五、修改影响预判（若未来编码）
- `lib/src/`：拆分平台无关业务 DTO/文档格式适配层、Android 具体存储/服务。
- `lib/main.dart`：根据平台加载对应入口/UI（现有仅 Android 预览，代码未改）。
- `pubspec.yaml`：富文本包、适配平台的存储/网络依赖。
- `.github/workflows/flutter-preview.yml`：为 Android、Web 独立编译与测试，避免 UI-only 预览脚本被误用为生产部署。
- 新增网页端和可能的私有 API 工程位置暂未决定，**本轮均未创建这些文件**。
- 已确认现有日记、笔记、长期追加保存和 WebDAV 手动优先约束不得取消。

## 六、最小验证样例
- 双端一条普通笔记含 H1、颜色、任务清单、图片和中文：Android 产生 JSON→PC Web 编辑→同步→Android 读取后字节含义与格式一致（Canonical comparison，非每次随机运行时节点 ID 相同）。
- 同一天三个长期追加仅修改其中一个，WebDAV 往返后保持三个 appendId、时间、顺序和独立 revision。
- 手机离线时仍可编辑并可靠本机保存；PC 浏览器脱网时显示“未保存到服务端”，不冒充已保存。服务器关闭或坚果云不可用时不会导致 Android 丢数据。
- PC 改动尚未同步而手机再次修改同一记录时，不发生盲目覆盖。
- 测试浏览器跨域 WebDAV 的 OPTIONS/鉴权失败、附件上传中断、超限响应与错误恢复，区分本机/服务端/云端状态。
- PC Web 公网公开服务必须完成认证、授权、HTTPS、XSS 与文档附件安全审查。
- 许可、客户端平台与内容可达性证明完成前不能说「已经实现 PC 网页编辑」。
