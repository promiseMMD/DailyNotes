## 二、阶段 1：和原版尽可能一致的交互行为基线

### 2.1 真实原版工具栏模式（已读取锁定源码）

源码：`frontend/appflowy_flutter/lib/plugins/document/presentation/editor_plugins/mobile_toolbar_v3/toolbar_item_builder.dart`。
- **默认插入光标**：`+` → `Aa` → 待办清单 → 项目符号列表 → 附件/媒体 → 编号列表 → 粗体 → 斜体 → 下划线 → 删除线 → 颜色 → 撤销 → 重做。
- **列表内光标**：`+` → `Aa` → 减少缩进 → 增加缩进 → 待办清单 → 项目符号列表 → 编号列表 → 粗体 → 斜体 → 下划线 → 删除线 → 颜色 → 附件/媒体 → 撤销 → 重做。
- **非折叠文字选区**：`Aa` → 粗体 → 斜体 → 下划线 → 删除线 → 颜色；符合条件的单段文字选区增加链接操作。
- 编辑器容器在 `editor_page.dart` 配置原版工具栏高度 42（Flutter 布局逻辑量，不保证任意设备物理像素尺寸）；工具栏横向滚动并随键盘/选区状态切换。
- **分阶段注意：** 虽然部分完整菜单功能在阶段 2～4 才补齐，但最终原版按钮顺序已由 DN-181 确认；首期开发预览不能用占位假按钮宣称功能完成，必须清晰区分开发原型与已可用内容。

### 2.2 必须逐个讨论的基础交互

| 能力 | 应观察/复刻的 AppFlowy 行为 | DailyNotes 阶段 1 需要的验收 |
|---|---|---|
| 进入新文档 | 一步直达正文、弹出键盘 | 日记/笔记/长期追加共用编辑器；空文档含合法初始段落，不崩溃；不强制先填标题 |
| 段落/标题 | H1/H2/H3 是块类型，不只是字体变大 | 相互转换后文本与光标位置正确；撤销与重做恢复结构 |
| 文字样式 | 折叠光标影响后续输入，扩展选区影响既有文字 | B/I/U/S 连续切换、跨行选区、切换区块后不串样式 |
| 列表/清单 | 清单勾选、编号、项目符号、缩进/退格 | Enter 新项、空项结束、Backspace 转换、嵌套缩进、勾选状态重启后持久 |
| 工具栏 | 默认/列表/选区三种分组，键盘上方横向可滚动 | 顺序、状态切换、横滑位置、触控反馈、键盘显隐不乱跳 |
| 撤销/重做 | 对文本和文档区块都生效 | 插入、删除、格式、列表转换能成对还原，不误提交长期追加 |
| 中文 IME | 拼音组合、候选确认、长按选区 | 不丢字、不重复、不错误断词；小米/第三方键盘实机复核 |
| 长文档 | 光标始终可见、滚动可跟随选区 | 长文、分屏、横竖屏、软键盘高度变化后不遮挡正文 |
| 记录持久性 | 编辑器状态和正式数据不是同一概念 | 日记/笔记按各自自动保存、长期追加保留草稿/正式提交边界；SQLite 事务成功才显示已保存 |
| 文档序列化 | Document JSON 保存节点/Delta | 关闭/重启后段落、标题、列表、文字样式与选区相关语义可重新阅读，未知区块不被破坏性覆盖 |

### 2.3 第一阶段的拟议交互规格（尚待用户逐项讨论）

1. 日记、笔记、长期追加都进入同一编辑器主体；顶部业务标题/日期根据内容类型变化，正文文档区、选择菜单和工具栏保持统一。
2. 非编辑阅读状态不常驻键盘格式栏；进入正文获得焦点后展示接近 AppFlowy 的键盘顶部工具栏；长按文字形成非折叠选区时切换为原版选区格式栏，文字附近的 Android 复制/剪切/粘贴等操作仍保留。
3. H1/H2/H3、段落、列表转换必须修改文档结构并支持撤销/重做；日记的「无需标题」与正文 H1 块是不同概念。
4. 清单勾选属于文档内部区块，不自动成为 DailyNotes 独立「待办」实体；涉及跨模块映射必须以后明确批准。
5. 默认不为快速输入单独创建一个简化编辑器；进入路径快，但工具栏/区块体系保持完整长期目标。
6. AppFlowy 具体视觉样式必须通过锁定源码生成的可比对截图/实机校验，不能仅凭旧宣传图承诺「像素级相同」。

## 三、阶段 2～5 的差异管理原则

- 阶段 2：原版 Aa 面板的 HeadingsAndTextItems / BIUSItems+ColorItem / BlockItems+AlignItems / FontFamilyItem+IndentAndOutdentItems 四行逻辑必须逐项核对；`+` 的 TypeOptionMenu 不可替代成 DailyNotes 自创六宫格。与阶段 1 重叠功能只补齐菜单入口和状态。
- 阶段 3：媒体/表格需要真实内容处理、持久化和附件字节校验；不能只保存文件路径或假图片。图片/附件的本机权威仍在手机。
- 阶段 4：折叠、代码、公式、引用、日期、提及等均需要文档结构、输入交互和退出重进保真；具体功能对照官方完整 App 移动端，而非独立包演示。
- 阶段 5：按「同一文档、同一操作脚本、原版截图与 DailyNotes 截图对照」核验布局和操作结果；审查输入法、长文、深浅色、触控区域、横竖屏、动画、系统返回、撤销及 PC 数据互通。各前阶段也必须各自有自动化测试和保存断电恢复测试。
- 所有条目需有：上游功能来源文件、阶段、状态（未开始/开发中/已实现并验证/受限或暂缓）、差异原因、替代交互/后续处理、自动测试、真机结果、截图证据、用户是否批准差异。

## 四、必须保持的 DailyNotes 自有边界

- DN-187 手机是唯一权威存储，PC 浏览器不是第二套权威数据库，PC 写入必须由手机持久化 ACK 才算保存。
- DN-183 富文本优先以 AppFlowy Document JSON 保存，业务 ID、revision、appendId、附件身份和格式迁移独立。
- DN-020/021 日记自动正式保存；DN-045/047 笔记自动本机保存和失败保护；DN-009/010 长期追加草稿与正式提交边界。
- DN-191 家庭 LAN 首期最低必要访问控制；DN-192 优先功能与体验，不再反复扩大非阻断的证书安全讨论。
- WebDAV 始终由用户手动点击启动；编辑器任何菜单/同步事件都不得自动触发。
- 代码许可、依赖版本、上游完整 App 特有插件与素材资产均需在实现前合规核验；相似外观与交互不等于直接复制上游所有源代码。

## 五、当前待定的重要产品细节

- 编辑器顶部的「文档标题/日期」与正文 H1 的精确位置、是否显示可编辑独立标题及各模块差异；不强制先填标题已确定。
- 原版当前移动端的图片、菜单和高级块实际视觉与 2026-11-15 锁定源码是否对应，需用目标 APK / 截图核对。
- 第一阶段可运行预览如何显示尚未实现的高级功能：不得出现误导性可点击假按钮，也不能借此永久删减已批准的目标。
- 技术依赖与完整 App AGPL / 独立编辑器 MPL 授权路径、编译体积和实际 Android 16 兼容性需最小 PoC。
- 首批验收是否采用一组固定测试文档（至少：普通中文长文、列表及清单、混合标题与文字样式），建议保留为全阶段回归样例。
