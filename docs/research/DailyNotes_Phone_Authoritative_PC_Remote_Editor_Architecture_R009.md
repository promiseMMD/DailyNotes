# DailyNotes 手机唯一权威存储、PC 远程编辑终端架构决策 R009

- 日期：2026-11-15
- 规范基线：`docs/requirements/DailyNotes开发规范_V2.60.md`，DN-001～DN-186。
- 决策背景：用户明确补充「WebDAV 由我人工自己手动点击同步；手机作为可靠存储；PC 上编辑的内容也同步到手机上」。此前 DN-186 对两端分别可靠持久化的表述没有准确表达该架构，需以新决策 DN-187 明确覆盖。
- 状态：用户已经确认核心架构原则；物理实现、主机生命周期和验收仍待技术设计。**本研究记录不是代码实现。**

## 1. 一句话不可偏离原则
**Android 手机是 DailyNotes 唯一权威的正式数据存储中心（single source of truth）；PC 是通过局域网连接手机的远程富文本编辑终端（remote editing client），而不是第二套权威数据库。PC 上的正式编辑必须传回手机，经手机校验并成功持久化后才算「已保存」。坚果云 WebDAV 完全由用户主动手动触发，局域网实时同步不会自动触发 WebDAV。**

未来接手本项目、讨论数据库、编辑器、同步、部署、恢复或验收时，必须先读取最新规范 DN-187 和本记录，不得回退到「手机/PC 各自维护独立权威数据库再互相合并」的默认方案。

## 2. 正式权威与非权威边界

### Android 手机（权威端）
- 唯一正式业务数据库和数据权威：日记、笔记、长期记录、追加项、正式 revision、删除/回收站状态、附件元数据和业务关系。
- 保存 AppFlowy Document JSON 正本、DailyNotes 业务 ID、revision、appendId、格式版本及附件稳定 ID/校验信息。
- 负责对 PC 请求执行鉴权、revision/CAS 检查、原子写入、持久化事件/outbox、附件内容落盘和历史版本管理。
- 本机离线可独立创建、编辑、读取和保存；不依赖 PC、LAN、WebDAV 或服务器可用性。
- 用户手动点击 WebDAV 同步时，以手机权威数据为源执行备份/增量同步和恢复管理；LAN 变化本身不得自动上传 WebDAV。

### PC（远程编辑端）
- 提供桌面浏览器完整富文本编辑、键盘/鼠标/大屏交互。
- 打开记录时从手机权威端读取记录内容和 revision；编辑操作通过局域网 API/实时通道提交到手机。
- PC 可保留临时编辑缓冲、浏览器恢复草稿/离线队列以防意外丢字，但它们**不是正式权威数据**，不得宣称已经「保存到 DailyNotes」或成为独立的第二份正式业务数据库。
- 手机离线或连接中断时，PC 可以明确标记「仅保存在此浏览器的未提交草稿」，保留可恢复草稿；恢复连接后用原始 baseRevision 提交。若手机端版本已前进，必须冲突保护、保留草稿并请求处理，禁止最后写入覆盖。
- 手机确认持久化成功后，PC 才能显示「已保存到手机」。若仅 WebSocket 发出/收到通知、内存缓冲、IndexedDB 临时写入或 API 请求已发送，均不能当作手机正式保存完成。

## 3. 局域网双向体验的准确含义
- 用户可在手机或 PC 任一端发起编辑；两端在线时另一端自动收到更新，追求低延迟/毫秒级交互体验。
- 数据权威仍然单一：PC 发起的编辑最终由手机提交并持久化；手机本地编辑也直接落在手机权威数据库，再通知 PC 更新。
- 「双向」指双端都可发起编辑和双向传递变化，**不表示两端都是独立权威数据库**。
- 首期可采用手机权威 HTTP API + WebSocket 变更通知 + revision/CAS + 持久化事件序号/断线补齐。PC 只发送意图/增量或提交后的文档快照，由手机执行最终校验与落盘。
- 两端同时编辑同一篇文档的逐键级协作（CRDT/OT/操作合并）仍须单独验证；不允许用整篇 JSON 的 last-write-wins 假装实时协作。未实现安全操作级合并前，需保留 PC 草稿、识别 revision 冲突并提供恢复路径。

## 4. WebDAV 的唯一职责和触发条件
- 坚果云 WebDAV 是手动备份/增量同步与恢复通道，不参与局域网编辑的热路径。
- 只有用户主动点击明确的「同步」操作才启动 WebDAV；局域网事件、自动保存、WebSocket 通知、PC 连接/断开、应用启动或后台定时器均不得隐式触发 WebDAV。
- 以手机权威数据库和持久化 outbox 为同步源；PC 不维护第二份独立 WebDAV 账户/同步队列，不因 PC 编辑直接上传 WebDAV。
- WebDAV 已同步/已备份状态与手机本机保存、LAN 送达、PC 草稿状态分别展示，不得混淆。
- 远端备份失败不能回滚或损坏手机权威数据；远端不一致/恢复前先校验版本与附件完整性。

## 5. 手机作为服务器/权威端的工程含义
- 优先评估手机直接承载局域网 API/WebSocket 服务，使 PC 请求直接落到权威数据库，避免 Windows PC 中间数据库再回传手机造成双主问题。
- 但 Android/HyperOS 后台限制、息屏后服务存活、Wi-Fi 漫游、IP 变化、用户强制停止、耗电和权限均须实机验证；不能仅因架构上希望手机做服务端，就宣称可在任意息屏状态持续提供服务。
- 若手机服务暂时不可用，手机本地记录继续工作；PC 无法提交到手机，只能显示并保护未提交草稿。
- 服务发现、设备配对、访问令牌、局域网暴露范围、TLS/WSS 或等效安全边界、应用进程恢复与端口冲突均待设计。
- 若后续发现手机后台服务无法达到需要的可用性，可讨论受限的辅助服务/中继，但不得因此将 PC 提升为第二权威数据中心；必须由用户批准新的权威边界变更。

## 6. 富文本与历史记录约束
- 正文仍遵循 DN-183：AppFlowy Document JSON 作为富文本正本，DailyNotes 自己维护业务 ID、revision、appendId、格式版本、附件身份和迁移策略。
- PC 编辑器必须与手机兼容同一文档格式；PC 不可悄悄转换成 Tiptap JSON 并作为唯一正本，也不得丢弃未知区块。
- 普通日记、笔记、长期记录追加、草稿/正式提交、删除状态、回收站及附件均由手机权威数据层管理。
- 长期记录每次 append 保留独立业务 ID 与时间；PC 修改一个追加不能重写/覆盖其他追加历史。
- 图片/附件上传到手机权威存储并校验成功前，PC 不得把含缺失附件的文档标记为「已保存到手机」。

## 7. 状态机建议（待实现与验收）
PC 单条编辑的可见状态至少区分：
1. `编辑中`：尚无提交。
2. `等待手机确认`：请求已发出但未获权威提交回执。
3. `已保存到手机`：手机已原子提交正文、业务 revision、必要附件引用和持久事件。
4. `手机不可达·本地草稿`：仅 PC 临时草稿，可恢复但不属于正式记录。
5. `版本冲突·草稿已保留`：手机 revision 与编辑起点不一致，未覆盖手机内容。
6. `WebDAV 待手动备份/已备份`：独立于上述状态。
手机端状态则区分本机保存与 WebDAV 备份，不应因 LAN 推送成功就误报 WebDAV 完成。

## 8. 必须验收的 P0
- PC 创建/编辑/删除日记和笔记，手机数据库成为唯一正式记录来源；手机关闭/重启后数据仍在，PC 临时缓存清空不损失已确认保存的数据。
- PC 输入后断开 LAN：未提交内容明确保留为本地草稿；不得显示「已保存到手机」；恢复连接后提交并由手机落盘。
- 手机已被另一端更新 revision 时，旧 PC 草稿提交被拒绝或安全合并；双方内容都可恢复。
- 手机息屏、切后台、HyperOS 省电、Wi-Fi 切换/断开/重连时，测出 LAN 服务可用性；手机本地记录始终可用。
- 手机 WebDAV 按钮不被任何 LAN 事件自动触发；在没有用户点击时检查 WebDAV 请求计数为零。
- 用户手动触发 WebDAV 时，备份源完整包含手机权威数据、revision、删除墓碑、附件；恢复演练后仍能打开所有富文本和附件。
- PC 临时草稿与手机正式 revision 的状态准确；杀浏览器、刷新、关机、缓存清理后分别验证草稿保留策略与数据边界。
- 富文本 H1/格式/列表/图片/附件在 PC→手机保存→手机重启→PC 重开全链路无损。
- 性能分别测消息到达、手机落盘回执、PC 更新显示；以实际设备/网络测 p50/p95/p99，不用单次最小值宣称「毫秒级 SLA」。

## 9. 决策状态
**用户已确认**：手机是唯一可靠/权威正式存储；PC 是局域网富文本编辑终端；PC 编辑内容必须传回手机保存；手机与 PC 在线时自动低延迟双向更新；WebDAV 只由用户手动点击触发。

**仍待设计/实测**：手机 HTTP/WebSocket 服务的进程模型及息屏可用性；数据库具体 Schema；PC 临时草稿实现；首期保存级同步与未来逐键协作边界；鉴权与密钥生命周期；附件传输；LAN 性能阈值；冲突 UI；Android/Windows 真机故障注入。

## 10. 与历史规范关系
- DN-187 是 DN-183～DN-186 的最新架构澄清/覆盖条款。
- DN-186 中「每端本机安全提交并各自持久化」的表述，**仅保留为传输/通知/版本校验等机制参考，不再表示 PC 有独立权威业务数据库**。
- DN-185 的局域网私有范围、安全约束仍有效，但「不指定唯一权威」由 DN-187 覆盖。
- DN-184 的 PC Web 编辑入口、DN-183 的 AppFlowy JSON + DailyNotes 业务层混合架构仍有效。
- 本条不授权编码；必须先完成架构和故障恢复验收设计，再按用户确认进入实现。
