## 一、已确认的产品分层

统一编辑器三段式职责划分：
1. **DailyNotes 业务信息区（上部）**：依据当前业务类型呈现其记录身份、日期与标题元数据；不是独立的富文本编辑器，也不通过正文 H1 伪装业务标题。
2. **AppFlowy 风格文档正文区（主体）**：日记、普通笔记、长期记录一次追加均使用同一套富文本 Document JSON 兼容编辑体验；区块、光标、选区、工具栏、`+`、`Aa`、撤销重做及键盘行为尽可能与 AppFlowy 完整应用保持高一致性，不创建三套不同编辑引擎。
3. **临时编辑控制区（由系统/键盘/上下文呈现）**：AppFlowy 方式的动态键盘上方工具栏与菜单；不在阅读态为了显示更多 DailyNotes 业务内容而强制占据正文画布。

业务信息应以 DailyNotes 自身稳定业务 ID/日期时间/修订字段维护；富文本正本由 Document JSON 表示。正文 H1 是用户的文档内容，不与业务标题/日期强制绑定或互相覆盖。

## 二、三种内容类型的具体差异

| 编辑对象 | 顶部业务信息（确认方向） | 共用 AppFlowy 正文 | 保存边界 |
|---|---|---|---|
| 普通笔记 | 文档标题可编辑（独立于正文 H1）；是否允许空标题、缺省标题、具体显示位置和字数限制仍待讨论 | 同一完整编辑器；以正文为主 | DN-045/047：输入有效内容后自动本机正式保存，失败不能误报 |
| 普通日记 | 日期信息与可选标题；不强制先填写标题或分类，打开新日记直接聚焦正文 | 同一完整编辑器；日期不是正文自动插入的 H1 | DN-020/021：自动正式保存，一天可多篇 |
| 长期记录追加 | 所属长期记录名称、当前追加日期/时间信息；具体日期调整、展示/编辑权限及记录时间口径后续细化 | 每次追加正文仍使用同一完整编辑器，追加 ID 与时间独立保存 | DN-009/010/013：新增追加是草稿，用户明确提交才成为正式追加；已有追加项顺序和时间不可丢 |

注意：仅**业务信息区的内容随类型变化**；正文工具栏、菜单功能、选区、撤销与 Document JSON 语义保持共同实现。用户在笔记或日记中打出的 H1 与业务标题是两个不同对象，不自动双向复制。

## 四、第一阶段建议进一步确定的交互（均未自动升级为已确认）

1. **编辑器顶部业务区是否随正文滚动**：更贴近 AppFlowy 的方案是标题和文档共同在可滚动区域内，顶部仅留返回/必要操作；若日记日期始终悬浮，可能占用小屏空间。建议先采用「业务标题与正文一起滚动」的候选，仍待用户确认。
2. **标题默认值**：笔记新建时是否必须输入标题？已确认日记不强制标题，笔记目前只确认可编辑标题方向，默认命名规则待定；不应在不输入标题时丢弃有正文的记录。
3. **日记业务日期**：顶部显示记录日期，能否改日记归属日期、跨日编辑如何处理、日期与创建时间如何区分，待讨论；不能只依赖正文文字来判断日期。
4. **长期追加时间**：实际提交时间、用户选择的业务日期、草稿创建时间可能不同，须待讨论区分，不在设计草图中偷定全部语义。
5. **键盘工具栏**：完全沿用锁定的 AppFlowy 完整 App 源码三态按钮集合；审查图标尺寸/空隙、滚动和键盘/菜单切换，不引入自创六按钮简化方案。
6. **保存状态**：只有手机真实本机持久化成功才能显示「本机已保存」；长期追加草稿不得显示「正式追加已保存」，手动 WebDAV 必须保持独立状态。
7. **基本验收**：同一段中文文本分别从日记、笔记、长期追加打开，标题和日期字段不会被存入正文作为伪 H1，正文 JSON 往返不丢段落/格式；返回/重新进入不丢内容；长文、键盘、软返回、中文输入时业务头与文档焦点互不干扰。

## 五、工程可行性与实现边界

- AppFlowy 完整应用 `frontend/appflowy_flutter/lib/plugins/document/presentation/editor_page.dart` 的 widget 暴露 `Widget? header` 并传递给 `AppFlowyEditor`：从代码层面支持编辑器容器有 header slot，但不表示将 DailyNotes 元数据直接塞入这个 header 就天然满足布局/事务要求。实际实现应通过可验证的 Flutter 控件结构与稳定业务模型隔离。
- 不把业务标题、日期、记录 ID、时间戳写成正文 H1 的唯一存储正本；正文中用户自己插入的标题是正常 AppFlowy 区块。
- 当前仓库仍是 Flutter UI-only 结构预览；本研究不说明编辑器和数据库已实现。
- 下一步讨论聚焦**「顶部业务标题是否与正文一起滚动」**，再议标题留空的默认行为与长文滚动；不是重新讨论 TLS 或后台安全。
- 上游许可证、完整 App 插件与独立 editor 包区别、真实 Android 16 输入法和构建兼容性，正式开发前仍需核验。
