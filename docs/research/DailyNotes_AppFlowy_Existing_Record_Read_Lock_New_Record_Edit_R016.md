# DailyNotes × AppFlowy 第一阶段：新建即编辑、已有记录默认锁定阅读 R016

- 日期：2026-11-15。
- 规范基线：DailyNotes开发规范 V2.70 / DN-001～DN-196；用户本轮明确确认「新建记录直接弹出键盘，打开已有记录默认阅读模式，点击解锁按钮才可再进行编辑」。
- 属性：已确认产品行为的技术与体验影响记录；本轮不编码、不构建 APK、不主张真机通过。与 R014 的五阶段总体功能清单、R015 的业务信息与正文共滚方案保持兼容。
- 范围：统一的 AppFlowy 风格手机编辑器；普通笔记、普通日记、长期记录新追加，以及允许修改的既有正式记录。**这里的「锁定/解锁」是防误编辑的 UI 状态，不是加密、密码或登录认证。**

## 1. 用户已确认的四项核心规则

1. **新建记录直接进入编辑状态**：用户通过既定快捷入口/上下文动态加号新建普通日记、普通笔记或点击长期记录「追加」创建新的追加草稿，直接打开同一 AppFlowy 风格编辑器，正文获得焦点、系统键盘自动弹出、编辑工具栏按原版动态显示。长期追加仍是草稿，只有用户明确提交才变成正式追加。
2. **打开已有记录默认阅读状态**：从日记时间流、笔记列表/文件夹/搜索或长期记录已保存的内容进入阅读时，默认不得直接改写正文；不自动聚焦文本，不弹键盘，不显示编辑工具栏。若是业务上支持编辑的已有记录，继续遵循下一条进行解锁；并不借此新增/授予对所有历史追加项的修改权限。
3. **点击「解锁」才能修改**：已有记录的编辑需由用户明确点击页面上的解锁按钮打开编辑状态。仅轻触正文、滚动或选择文字不能绕过解锁。解锁是防误触，不需要 PIN、指纹、密码或联网验证，也不影响手机唯一正式权威数据存储。
4. **同一编辑器、不同状态**：阅读和编辑之间使用同一文档渲染与业务身份，不另建一个功能缩水的阅读/编辑器，也不改变 DN-180/181/182、DN-193/194 的 AppFlowy 对标目标。业务头与正文仍按 DN-195/196 一起纵向滚动；锁定的操作入口属于必要页面控制，具体固定位置与外观待后续确认。

## 2. 建议实现的状态模型（以下实现细节不是用户逐项批准）

- `CreateEditable`：新记录。直接开启可编辑、正文焦点与键盘；仅持久化成功后报告已保存。若未输入任何有效内容，空白建档规则仍按既有未决项处理。
- `ExistingLockedRead`：打开已存在的记录。正文只读渲染；阅读、滚动、文本选择、复制、链接导航、非变更内容的查看可以保留；任何插入、删除、粘贴写入、格式修改、块拖放及清单勾选等**变更文档的操作都应在只读态阻止**；隐藏编辑格式工具栏和键盘。清单勾选也是内容修改，不能在锁定阅读态悄悄写入。
- `ExistingUnlockedEdit`：点击解锁进入可编辑状态，同一记录与正文继续显示；焦点/键盘是否立即弹出**用户尚未确认**，后续建议结合真机对标选择「解锁后等待点选正文」或「解锁后聚焦先前位置」。编辑操作仍受业务保存、冲突与历史版本限制。
- `SavingOrError`：如果编辑中出现未持久化内容或写入失败，返回/锁定/离开应遵守既有失败保护；不能因为切回阅读态而丢失草稿、误报已保存或覆盖唯一正本。

**建议但尚未批准**：可在解锁编辑后提供「再次锁定」入口，一键收起键盘并恢复防误触阅读态；具体按钮外观、位置、动画与触发保存的时机需确认。再次打开正式记录默认锁定，但未保存内容必须先完成恢复/风险保护，不得无提示丢失。

## 3. 跨业务影响

| 模块 | 已确认行为的影响与注意 |
|---|---|
| 普通笔记 | 新建可直接输入，已有默认只读，解锁后才允许修改标题与正文；DN-045/047 自动本机保存及失败警示继续生效 |
| 普通日记 | 新建立即弹键盘；已有默认阅读，解锁后编辑；支持一天多篇，DN-020/021 自动正式保存语义不变 |
| 长期记录 | 点击「追加」新建追加草稿直接可写；浏览已正式保存的内容默认阅读。历史追加项是否提供编辑入口及权限由既有业务规则/后续讨论确定，不因本条自动扩大 |
| 文档内勾选清单 | 锁定阅读下不可直接勾选修改文档；解锁后才允许改变选中状态；不自动创建独立待办实体 |
| AppFlowy 工具栏 | 阅读态不显示键盘上方编辑栏；编辑态使用 R002 锁定的普通/列表/选区状态工具栏，不擅自删减 |
| 标题及日期 | DN-195 独立业务元数据在阅读态同样只读，不允许点击字段绕开解锁；仍和正文同一内容区滚动 |
| PC 局域网 | 本条只确认 Android 手机编辑器 UI，**不擅自将此只读默认规则推广为 PC 端编辑授权协议**，PC 仍遵循 DN-187、DN-191 |
| WebDAV | 不因锁定、解锁、进入阅读或输入动作自动触发；用户主动手动同步保持不变 |

## 4. 第一阶段建议验收（未来编码后执行）

1. 新建笔记：进入即焦点在正文、键盘出现，录入中文后本机保存并重进可见。
2. 新建日记：无标题/分类向导、直接正文输入；自动保存即正式日记，不误当长期草稿。
3. 长期记录新追加：直接进入正文与键盘，退出时若有未正式提交内容按 DN-010 给出草稿保护。
4. 已有笔记/日记：从列表或搜索进入，正文可阅读滚动、选中文字复制；键盘不弹出，编辑工具栏不常驻。
5. 已有记录锁定态：点击正文、标题、按键、粘贴、格式动作、清单复选框均不修改内容或业务元数据。
6. 已有记录点击解锁：同一正文切为可写，不重建/清空文档，不改变滚动位置或现有选区内容；随后输入、格式和撤销重做实际生效。
7. 关闭并再次打开已有记录：默认重新进入阅读态；以前的编辑已真正本机落盘，失败不能误报。
8. 手机保存失败、强杀恢复、多个版本冲突下，不能因锁定状态切换而丢正文/附件/历史修订。
9. 中文拼音输入、键盘弹出/隐藏、H1/列表/清单/附件在两种状态切换下不崩溃或误修改。
10. 三类型业务信息均随正文共同滚动，解锁按钮不因滚动完全不可找到；具体按钮可达性和外观仍待确认。

## 5. 后续最值得讨论的两个问题

- 解锁已有记录后：**直接弹键盘**，还是进入可编辑状态但**等用户点击正文后弹键盘**？此问题尚未由用户选择，不应偷定。
- 解锁后是否保留「重新锁定」入口、该按钮的固定位置/可达性与切换时保存失败行为？原则上需要易操作但不能在未保存内容上直接丢弃。
