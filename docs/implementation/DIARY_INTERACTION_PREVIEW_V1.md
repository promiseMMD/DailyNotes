旧 APP 迁移代码或 WebDAV 逻辑**。

## 可操作交互与严格限制

1. 日记页第五个「新建」：进入轻量正文编辑器，自动保存本机
   **测试数据库**；仅事务提交成功后显示“本机已保存”。
2. 返回：写入未完成或失败时阻止误离开，允许重试或复制。
   强制杀进程可能丢失最后尚未提交的内存草稿，必须作为 P0。
3. 保存后回首页展示真实已提交日记；点击旧条目可再次编辑同一 ID。
   每次成功修改生成不可变 revision 与持久化 outbox intent。
4. 日记顶部搜索：按已提交的正文过滤，不修改数据库。
5. 排序：底部选项可在当前测试列表切换最近/较早编辑优先。
   官方排序字段和默认规则仍待批准，未被升级为 V2.51 需求。
6. 抽屉「日历总览」：只显示测试列表中存在的日期、真实条数；
   点击日期回日记页面过滤；删除日期筛选不改数据。
7. 「我的」只额外显示独立标记的测试日记条数，其他业务统计
   仍未检查/未统计，绝不假造跨模块汇总。
8. 没有通过正式 schema 设计的笔记、待办、知识库、长期记录
   仍保留未完成提示；不为了演示而私自复制普通日记结构。

## 未闭环的 P0 / P1

- P0：最终普通日记 schema、身份 ID、日期/分类元数据未批准。
  测试数据库与未来正式数据库不可直接等同，不做自动迁移。
- P0：保存故障时未提交草稿只在内存中；进程意外结束可能丢失。
- P0：尚未具备 WebDAV 增量同步、正式本机备份与真实恢复验证；
  不可将测试日记视为已安全归档。
- P0：未在目标 Android 机型验证安装覆盖、权限、切前后台、
  断电、存储不足和数据库损坏恢复。
- P1：搜索索引、分页性能、日记创建日期与修订日期分离、
  分类管理、回收站、永久删除和长记录追加仍未完成。
- P1：当前展示的是**最后成功编辑的日期**，不是正式定义的
  日记创作日期，需待日期语义确认后正式实现。

**正式发布门槛：** DN-149/DN-152 的四阶段全部验证、
P0/P1 零未解决后，才能考虑存储真正重要的数据。
