# DailyNotes × Moodiary：UI 候选版（不改变 V2.51）

**状态：视觉候选，不等于已批准的最终设计。**

## 参照依据与边界

- DailyNotes 正式需求台账：`docs/requirements/DailyNotes开发规范_V2.51.md`，DN-069/070/154–175，保持原样。
- Moodiary 实际参考源码：`promiseMMD/codex-learning` 分支
  `moodiary-v3-w9-8-4-31-permanent-application-id-20261110`，
  `moodiary-v3-w9-5-2/overlay/mobile/lib/app/home/mod_month_page.dart`
  及 `mod_month_day_preview.dart`。阅读得到的可迁移设计方向：
  月份/日期分组、紧凑预览、顶部工具按钮、优先展示正文；
  **没有复制 Moodiary 的业务数据、月度存储或同步代码**。
- 本候选不以 Moodiary 的实际完工程度代替 DailyNotes 验收。
- 用户明确要求改善目前过度简陋的 APK：本轮先提高页面可辨识度、
  阅读层次和紧凑程度，不为“好看”而假造日记、同步状态、备份状态。

## 本轮修改位置 / 影响范围

1. `lib/src/preview/soft_components.dart`：统一暖纸白底色、鼠尾草色、
   标题字级、段落分区、空状态、顶部双标签、强调型加号。
2. `lib/src/app.dart`（仅 UI 部分）：
   - 日记：文档阅读型两分区；无顶部快捷录入卡片、无虚构示例记录；
     长期记录与普通日记保持两套内容；
   - 抽屉：非全屏 76% 宽，十项独立入口顺序不变，设置固定底部；
   - 底栏：四个主页面 + 动态新建按钮仍为第五位置，保留实际
     “功能尚未接入”提醒；
   - 待办 / 笔记：顶部横向指示条切换，保持互相独立的内容页面；
   - 我的：字数分类展开、足迹、回顾、回收站入口；
   - 健康检查：四类只读检查，不伪造“正常”或检测时间。
3. `test/moodiary_inspired_ui_test.dart`：导航、菜单顺序、360px 窄屏回归。
4. `test/ui_preview_screenshots_test.dart`：实际 Flutter Widget 树生成
   393x852 截图，供人工查看，不作为真实手机的截图。
5. `.github/workflows/flutter-preview.yml`：分析、单元/集成/旧 UI
   测试、新视觉测试、截图上传、Debug APK 构建全流程。

## 已确认与待定的区分

- **保持确认：** DN-154/155 第五动态加号；DN-069/164 顶栏按钮；
  DN-165 非全屏抽屉；DN-161/162 文档流日记，顶部不放快捷输入；
  DN-169/170 待办双标签；DN-171/172 笔记；DN-175 只读健康。
- **仅视觉候选：** 页面引导文案、绿色深浅、字号/圆角/间距、
  底栏图标样式、图标选择、空态视觉、日期位置。
  这些没有自动成为新 DN 需求。
- **未实现：** 实际记录浏览、编辑器入口接入、自动保存生产集成、
  WebDAV、备份、AI、动态统计、正式截图逐图确认。

## 必须验证后才能说“预览 APK 已完成”

- 最终 SHA 关联 CI 所有测试均成功，尤其不能跳过
  `moodiary_inspired_ui_test`、截图生成和旧导航测试。
- 393x852 实际 Widget 截图：日记、抽屉、待办、笔记；
  应看见无重叠的工具栏、非全屏抽屉、突出第五加号。
- 360x760 窄屏打开数据健康页无 Flutter overflow。
- 健康、备份及同步状态不得伪造成功。
- 即使 CI 全绿也只能称“可安装的预览版”，不得声称真机视觉、
  生产数据安全、真实写入或最终 UI 已验收。

## 审查疑点

- 目前所有主页面仍只有空状态，未接真实数据；视觉改善后依然
  不是完整日记产品，需要下一阶段真正打通日记读取/编辑/回收站。
- 候选截图需用户确认是否喜欢其信息密度和 Moodiary 参照程度；
  不该因为 CI 通过就标记“设计已批准”。
- Moodiary 的月度时间块、月总结及日期导航属于另一软件的数据
  组织模型，不应默认复制为 DailyNotes 普通日记的业务规则。
