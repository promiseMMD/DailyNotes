## V3.69 新增确认项（DN-255）

## V3.70 新增确认项（DN-256）

- AppFlowy 侧重点：完整区块编辑体验、+ / Aa、选区工具栏、列表/清单、引用、代码、表格、媒体、区块移动、撤销重做及移动端键盘交互。

- 延续 DN-183：AppFlowy Document JSON 是既定正文正本路线；Moodiary Tiptap JSON 必须通过无损适配层转换，不能擅自替代正本。Android 与 PC 可采用不同引擎，但必须保持文档语义一致及往返无损。

## V3.72 新增确认项（DN-258）

- 用户同意普通表格最小结构为 1 行 × 1 列，不允许删除唯一剩余行或列使结构变成 0 行/0 列。
- 1×N 表格可以删除其他列，但不能删除唯一剩余列；N×1 表格可以删除其他行，但不能删除唯一剩余行。达到 1×1 后仍保留表格，可继续编辑、清空单元格或重新插入行列。
- 若要移除表格本身，必须使用 DN-257 整表删除并二次确认；不得通过删除最后一行/列绕过确认。
- 最小结构限制必须在共享文档操作/领域规则层落实，覆盖 Android、PC、Undo/Redo、批量操作及远程 API，不得只依赖 UI 隐藏按钮。
- 本条仅为已确认设计规则，不代表代码实现或测试已完成。

## V3.73 新增确认项（DN-259）

- 用户明确采用「手机端轻量编辑器 + PC Web 端专业编辑器」双层产品设计。
- 手机端优先快速记录、简洁高频工具、触控友好、阅读锁定/显式解锁和可靠本地保存；不得为了功能数量一致而堆叠专业菜单。

- DN-257/258 的表格删除与最小结构安全规则是共享领域规则，两端都必须遵守；复杂表格能力优先在 PC 端设计。合并/拆分等高级功能尚未获独立批准。
