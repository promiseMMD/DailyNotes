## 版本与交接约束

- **V3.12 的基线是 V2.77，不是 V2.51**。已从 GitHub 真实读取 V2.77，完整保留 DN-001～DN-203 的原文、核心架构约束和变更记录，新增 DN-204～DN-216；旧版文件没有覆盖。
- 手机是唯一权威正式存储，PC 为逐次手机确认的 LAN 远程编辑终端；坚果云 WebDAV 仅用户手动触发。业务数据保存与长期追加确认规则不得因编辑器设计而被修改。
- 3.0 最新确认事项包括 Aa 方案 A、半屏面板 B、遮挡滚动 B、系统返回 B、智能保存 B、R1 基础异常恢复、保存失败退出保护 A、ZIP 应急导出优先 A、标准 WinZip AES-256 ZIP 格式 A。

- 同步节奏为：**当轮记录决策 → 约 5～8 项或完整模块/重大架构/编码前提醒 → 用户批准后集中同步 GitHub → 读回核验版本、编号和提交 SHA**。

## V3.49 阶段新增确认项（DN-229～DN-240）

- 图片独立 Block、图片专用拖动手柄、远距离“移动到章节”；PDF 在正文使用紧凑卡片并进入独立阅读器。
- 录音“标记此刻”作为独立媒体元数据，无须解锁笔记；锁屏/后台播放是默认关闭的独立开关；PDF↔音频关系独立写入，自动跟随默认手动、可按需开启。
- 正文保存失败允许其他资料安全只读浏览，同时保留原活跃手机正文编辑会话；不得把 P2 误理解为禁止当前原会话内存编辑。
- 长期追加草稿只在所属长期记录详情展示；正式提交成功后返回所属长期记录并按 appendId 定位；三类业务的正式保存与草稿提交语义保持分离。
- 顶部正常状态使用轻量保存图标，点击查看详细；失败等风险持续显示。UI 原型、精确算法、性能阈值、AppFlowy APK 逐项对照均为待验证，不等于功能已实现。
- 详细决策、候选规则、历史轮次与验收缺口见 V3.49 第 13～18 节。V3.28～V3.49 为对话讨论轮次，不代表中间每轮均曾产生独立 GitHub 文件。
